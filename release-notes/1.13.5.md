# Hail 1.13.5

## System-app controls and verified freezes

- Restore upstream-compatible Shizuku Disable and Enable controls for retained system packages. Hail changes the stored enabled setting for the selected profile without reinstalling the package, and shows installation status separately.
- Verify each requested setting and preserve Android's error when a request is refused. Bulk and repeated requests use the same retained-package handling as individual actions.
- Fix a false failure when an installed-only Android query returns package metadata without `FLAG_INSTALLED`.
- Check disabled and stopped state after an accepted disable, including repeated requests. Request a force-stop only when the installed package needs it. A rejected disable does not force-stop the app.
- Correct explicit Enable requests that previously could leave a retained package at its default setting, and correct app labels in mixed operation results.

## Privacy and access controls

- Show the app and requested action before executing external links and intents. Hail-created shortcuts, the tile and notification actions use a private activity.
- Apply biometric protection to actions and relock the main screen after leaving.
- Protect Hail windows, suppress Android clipboard previews for copied data, and exclude Hail state from automatic backup and device transfer. Recent-app shortcut suggestions are opt-in.
- Allow local diagnostic events to be erased independently of exported files. Diagnostic recording remains off by default.
- Stop enabling Android's backup service when Hail is activated as an administrator. Require Island to acknowledge package-policy requests before reporting success.

## Performance and appearance

- Reuse app labels and package dates during each inventory refresh.
- Reduce redundant fuzzy-search work and avoid expanding every combination of polyphonic pinyin readings. Preserve alternate readings and keypad tone digits.
- Apply the GPT Mobile cyan-black palette and Proxima Nova fonts to XML and Compose screens. Dark is the default; Light and Follow system remain available.

## Android behavior and validation

Disabling is reversible and specific to an Android profile. The target app's files remain on the device. Separate profiles, privileged services and data previously shared with providers have independent lifecycles.

Shell-backed Shizuku uses Android's user-disabled state; root-backed Shizuku can request full disable. Android's protected-package and enabled-state restrictions still apply. A temporarily disabled-until-used package is not treated as a confirmed durable disable after a rejected request.

The release workflow requires passing unit tests, all 16 registered Android 16 device scenarios, upstream/fork comparisons and an optimized build before publication. It checks the APK package ID, version and existing fork signing certificate, verifies uploaded assets, and publishes the draft only after those checks. These automated checks do not establish physical ASUS handset behavior or every provider-specific Island/Dhizuku configuration.
