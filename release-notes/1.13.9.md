# Hail 1.13.9 (46)

## Individual Home screen shortcuts

- Repair automatic confirmation when a launcher displays both the publisher and target as “Hail”, including standard OEM confirmation dialogs.
- Recognize Nova Launcher's shortcut confirmation using its installed, localized resources. Nova identifies the preview with its own application name; the assistant checks the exact target, shortcut marker and Add control while rejecting widget and unrelated dialogs.
- Keep the assistant subscribed throughout the batch and allow launcher window transitions to settle before reporting an unsupported confirmation.
- Recover a missing success callback using Android's pinned-shortcut readback after the preceding confirmation has closed. An accepted request or a click alone never counts as a completed shortcut.
- Resume interrupted progress without discarding a late approval or duplicating a verified existing shortcut.
- Keep the display awake during an active automatic batch, including launcher confirmations that cover Hail. Pausing, cancelling, completing or deliberately locking the phone releases the bounded display lease.
- Limit shortcut icon dimensions and fall back to a normal icon when a particular icon cannot be loaded.
- Include shortcut progress, current request, match reasons and failures in opt-in diagnostic exports. Export metadata includes the saved batch state even when logging starts after a stall.

## Shortcut backup and restoration

- Permit Android to back up Hail's native shortcut metadata while continuing to exclude Hail app files and preferences from automatic backup/transfer.
- Regenerate missing icons for surviving app, tag and action shortcut records in bounded updates, preserving their IDs and private launch route. Retry incomplete first-open repair on a later foreground visit.
- Add Nova recovery guidance: recreate missing native Hail shortcuts before reapplying the original Nova layout backup. Nova-only backups cannot themselves reconstruct pin-only records Android has lost, and Hail cannot recover desktop positions already discarded by Nova without that layout backup.

## Main window

- Show a brief, count-only overlay after explicit freeze actions, including launcher and widget actions. Count newly frozen installed apps; repeated freezes, failures and retained uninstalled settings do not inflate the total.
- Use normal theme text colours for app names and risk labels in Home and Apps. Risk descriptions remain available as text.
- Treat installed system components without a launch screen as installed. A normal tap does nothing and shows no popup; explicit enable/disable controls remain available.
- Check launch capability before thawing an app or its associated tag, so tapping a background-only component does not change package state.

## App risk guidance

- Add a persistent sort control at the top of Apps, including Recommended first and Unsafe first. Unknown ratings stay last; search and app-state filters continue to apply.
- Expand rating explanations with the source snapshot, device-role overrides, and community-listed dependencies and dependents where supplied.
- Verify the bundled community catalog against its recorded checksum before using it. Ratings remain advisory; a community recommendation is not proof that every device feature will be unaffected.

## Shizuku integration

- Observe service connection, replacement and death, refresh package availability, and show connection/authorization status in Settings.
- Scope permission requests to the current screen and mode selection, with unique request identifiers and cleanup after cancellation, timeout or service loss.
- Replace the deprecated remote-process API with a bounded Shizuku UserService command path. Freeze/enable keeps its direct Binder calls and state verification.
- Add the core Java library desugaring required by Shizuku API 13.1.5 on Android 6. The current published API remains 13.1.5; no newer published alpha or beta was found in the upstream audit.

## Validation

The release gates include queue regressions for a missing callback at item 115 of 284, delayed readback and resume races, plus separate Android 16 launcher tests that place 284 individual native shortcuts on the standard launcher and an authentic Nova installation. The long tests use an app labelled “Hail” at item 115 and repeat the inventory to check that existing IDs are reused. Nova's APK checksum, signing identity, default Home role and actual resumed Home activity are required evidence. All existing device, upgrade, system-app and performance checks remain required, with additional launcherless-component and Shizuku lifecycle/command checks.

The supplied ASUS 1.13.8 diagnostic export contains session metadata only; it does not establish which failure stopped that phone at 115/284. Launcher-specific confirmation screens still require recognizable controls, and Android's one-time Accessibility permission remains necessary for automatic placement.
